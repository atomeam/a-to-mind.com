## Concept
A tiny local MLP (plain JS, 5-10-6) ingests DeviceOrientation (beta/gamma), DeviceMotion (acceleration magnitude), and a luminance proxy (from ambient light sensor or canvas average). It outputs parameters for a multi-sphere SDF (centers, radii, color bias). These drive a WebGPU fragment-shader raymarcher that visualizes the spatial “mind” on a central canvas. Simultaneously the same parameters are exposed as CSS custom properties that a CSS Paint Worklet reads to generate procedural living backgrounds, borders, and noise patterns on the surrounding UI panels and page chrome. Pointer clicks inject energy that temporarily biases the MLP inputs and SDF. Seal persists MLP weights + last parameters to IndexedDB. Fully offline single-file prototype with Canvas2D SDF fallback.

## Architecture
- Single index.html (progressive enhancement, offline after load)
- Tiny MLP: inputs [beta, gamma, accelMag, lum, energy], hidden 10 tanh, outputs [cx, cy, cz, r, hue, energyDecay]
- WebGPU: fragment shader raymarches 4 metaball-like spheres; uniforms updated each frame from MLP
- CSS Paint Worklet: registered via blob URL; paints noise + gradient + circle motifs driven by CSS variables (--mind-cx, --mind-r, --mind-hue, etc.)
- UI panels use `background: paint(living-chrome)` and border-image or mask
- IndexedDB store `f578-sdf-paint-mind` for MLP weights + params
- Sensors: DeviceOrientationEvent + DeviceMotionEvent (permission on iOS); luminance proxy via optional AmbientLightSensor or pointer brightness
- Chrome: status, energy readout, Seal / Reset / Inject buttons

## Expected outcome
Runnable prototype: tilting / moving the device (or mouse proxy) drives the MLP; the central SDF visualization morphs; surrounding panels and chrome continuously repaint with living procedural patterns generated by the same mind state. Clicks inject; Seal restores MLP and visual state across reloads. Works offline; graceful Canvas2D + CSS fallback if no WebGPU or Paint.

## Mechanics
1. Init MLP random weights (or load), zero energy.
2. Each frame: read sensors (or pointer proxy), run MLP forward, update CSS variables + WebGPU uniforms, step raymarch render.
3. Click: inject high energy at pointer, bias MLP.
4. Seal: serialize MLP weights + last params to IndexedDB.
5. Paint Worklet continuously reflects CSS vars into painted chrome.
